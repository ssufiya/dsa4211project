# Bayesian optimisation vs CMA-ES under low effective dimension

Does the performance of Bayesian optimisation (BO) and CMA-ES depend on the
**ambient dimension** D, on the **effective dimension** d_e, or on whether the
low-dimensional structure is **aligned with the coordinate axes**?

The hypothesis tested is that each method's behaviour follows from its
invariances and from what it must learn from data:

| Method | Rotation-invariant? | Must learn | Predicted weakness |
|---|---|---|---|
| CMA-ES | yes, up to box handling | full D x D covariance | slow adaptation in high D |
| GP-BO, ARD kernel | no | one lengthscale per axis | rotated structure |
| GP-BO, isotropic kernel | yes, up to box | one lengthscale | high D (no dimension can be switched off) |
| TuRBO-1 (trust-region BO) | no: trust region is an axis-aligned box shaped by ARD lengthscales | local GP + trust-region size | rotated structure; slow trust-region adaptation when D is large |

Authors: see [authors.md](authors.md). Report: [report/report.tex](report/report.tex).

## Data

There is no external data. All test problems are synthetic and generated from a
seed in `code/problems.py`. For a given (base function, D, d_e, alignment, seed)
every method sees the identical problem instance and the identical initial
design, so comparisons between methods are paired.

## Reproducing the results

Each command writes to `results/<experiment name>/` and skips runs that already
exist, so an interrupted run can be resumed by repeating the command.

```bash
# 0. Smoke test (about 15 s): checks the pipeline end to end -- just to test if everything is okay
python code/run_experiments.py --config configs/smoke.yaml --workers 2
python code/analyse.py --exp smoke

# 1. Pilot
python code/run_experiments.py --config configs/pilot.yaml --workers 4
python code/analyse.py --exp pilot

# 2. Main experiments

python code/run_experiments.py --config configs/main_dimension.yaml --workers 4 # dimension experiment: how does the ambient dimension D affect each method, and does rotation hurt more as D grows?
python code/analyse.py --exp main_dimension
python code/run_experiments.py --config configs/main_effective_dim.yaml --workers 4 # run the effective-dimension experiment: what happens as the number of important directions d_e grows?
python code/analyse.py --exp main_effective_dim

# 3. Follow-ups
python code/run_experiments.py --config configs/followup_approx_lowdim.yaml --workers 4 
python code/analyse.py --exp followup_approx_lowdim
python code/run_experiments.py --config configs/followup_cmaes_long.yaml --workers 4
python code/analyse.py --exp followup_cmaes_long

# 4. Follow-up investigations (numbers quoted in Section 5 of the report)
python code/investigate.py

# 5. Report
cd report && pdflatex report && bibtex report && pdflatex report && pdflatex report
```

Use `--dry-run` to list the runs a config will perform without running them.

**Runtime.** CMA-ES and random search take well under a second per run. GP-based
methods dominate: their cost grows with the number of evaluations (GP fitting is
cubic in n) and with D (more kernel hyperparameters for ARD). Measured on a
2-core cloud machine: the pilot (200 runs, budget 100) took about 30 minutes with
`--workers 2`; a single GP-ARD run at D = 30 took 40-110 s and a TuRBO run about
30 s. The main experiments
use budget 200 and D up to 100, so expect several hours; run them overnight with
as many workers as you have cores. TODO: record your own timings here.

## What each output means

* Performance measure: **simple regret** f(x_best) of the best point evaluated so
  far. Every problem has minimum value 0, so f itself is the regret. There is
  no observation noise, so the best observed value is also the true value.
* Budget: number of **objective evaluations**, including the `n_init` initial
  points. Wall-clock time is recorded separately (`wall_time_s`, and for GP
  methods `gp_fit_time_s` and `acq_time_s`).
* Figures per experiment: `_convergence`, `_final_vs_D`, `_ecdf`, `_walltime`, and
  `_rotation_effect` (rotated minus aligned median log10 regret with 95% CI).
* `summary_final_regret.csv`: median and IQR of log10 final regret per setting.
* `summary_vs_reference.csv`: paired per-seed difference in log10 final regret
  against CMA-ES, with bootstrap 95% CI and the fraction of seeds where the
  method beat CMA-ES.
* `summary_rotation_effect.csv`: rotated minus aligned median log10 final
  regret per method (unpaired bootstrap CI).
* `summary_diagnostics.csv`: mechanism diagnostics. For CMA-ES,
  `relevant_variance_fraction` = tr(A^T C A)/tr(C) of the final search
  covariance (isotropic value d_e/D). For ARD-GP on aligned problems,
  `relevant_recovered_frac` = fraction of the d_e shortest lengthscales that
  are truly relevant coordinates (also reported for TuRBO). For TuRBO,
  `restarts`, `n_expands`, `n_shrinks` and `final_length` describe how the trust
  region evolved; the full `length_history` is in each run's JSON.

## Implementation notes and known limitations

* GP-BO uses scikit-learn's `GaussianProcessRegressor` (Matern-5/2, outputs
  normalised, hyperparameters by marginal likelihood with restarts) and
  log Expected Improvement. The acquisition is maximised over a candidate set
  (uniform points plus perturbations of the best points), not by gradient-based
  multi-start optimisation as in BoTorch. This favours simplicity and
  transparency over raw performance.
* `refit_every: k` refits kernel hyperparameters every k iterations (the GP is
  still conditioned on all data every iteration) to keep D = 100 affordable.
* CMA-ES uses pycma's default population size and `BoundTransform` boundary
  handling, starts from the best initial point with `sigma0 = 0.5` (a quarter of
  the box width), and restarts from a random point if a stopping criterion fires.
* TuRBO-1 follows Section 3 of Eriksson et al. (2019) with the paper's default
  settings (unit-cube side lengths 0.8 initial, 2^-7 minimum, 1.6 maximum;
  success tolerance 3; failure tolerance max(4, D); restart with a fresh random
  design when the trust region collapses). One deviation: Thompson samples are
  drawn exactly over at most 2000 candidates instead of the paper's up to 5000
  with a scalable approximation.
